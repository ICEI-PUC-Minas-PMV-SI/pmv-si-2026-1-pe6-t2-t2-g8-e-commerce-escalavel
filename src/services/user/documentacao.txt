Fase 2 — Preparar o front-end da Etapa 3

A etapa da faculdade pede primeiro front-end web. Então depois de fechar a UsersAPI, o próximo foco é a interface.

Pelo enunciado, você precisa entregar:

visão geral da interação do usuário;
protótipo interativo/wireframes;
fluxo de usabilidade/fluxograma;
frontend web consumindo Web API;
testes de unidade;
controle de mudanças;
quadro GitHub;
contribuições dos membros.

Para sua parte de User, o front mínimo deveria ter:

Tela	Objetivo
Login	Autenticar usuário
Cadastro	Criar usuário customer
Perfil	Ver dados do usuário logado
Editar perfil	Alterar nome/e-mail/endereço
Trocar senha	Atualizar senha
Admin usuários	Listar usuários, apenas admin
Desativar conta	Soft delete

Ordem ideal do front:

Criar estrutura base do front.
Criar layout simples.
Criar serviço HTTP para auth/users.
Criar tela de login.
Salvar token no navegador.
Criar proteção de rotas.
Criar tela de perfil.
Criar tela admin de usuários.
Criar testes unitários básicos.
Documentar prints e evidências.








Fase 3 — Documentação acadêmica

Aqui é onde muita gente perde ponto mesmo com o sistema funcionando.

Você precisa preparar:

1. Documento de processos

Fluxos sugeridos:

Cadastro de usuário.
Login.
Usuário acessando perfil.
Usuário editando perfil.
Admin listando usuários.
Usuário desativando conta.

2. Fluxograma

Um fluxo simples:

Usuário entra no sistema
→ Tem conta?
   → Não: cadastro
   → Sim: login
→ API valida credenciais
→ Gera token
→ Front salva token
→ Usuário acessa perfil
→ Se role admin, libera painel de usuários

3. Wireframes

Telas mínimas:

Login.
Cadastro.
Home autenticada.
Perfil.
Editar perfil.
Admin usuários.

4. Registro de testes

Separar em:

testes de API com Postman;
testes automatizados com Jest/Supertest;
testes manuais no front;
testes de permissão admin/customer.

5. Controle de mudanças

Criar uma tabela tipo:

Data	Alteração	Responsável	Motivo	Status
26/04	Criação da UsersAPI	Marcos	Autenticação do sistema	Concluído
26/04	Teste cadastro/login	Marcos	Validar JWT	Concluído
26/04	Integração Docker	Equipe	Subir microsserviços	Concluído

6. Evidências GitHub

Prints necessários:

quadro Kanban/issues/projects;
commits;
contributors;
branches/PRs, se houver;
histórico da sua parte da UsersAPI.



7. Minha recomendação direta

Agora eu faria nesta ordem:

Conferir package.json, Dockerfile e server.js para garantir que qualquer pessoa consiga subir a UsersAPI.
Testar todas as rotas pelo gateway http://localhost:7000, não só pela porta 5001.
Criar uma coleção Postman da UsersAPI com register, login, get profile, update profile, update password, list users admin e delete user.
Rodar os testes automatizados e salvar print.
Padronizar/documentar os retornos JSON.
Decidir se vai adicionar /auth/me antes do front.
Começar o front web da Etapa 3 pelas telas de login/cadastro/perfil.
Montar os artefatos acadêmicos: fluxograma, wireframes, testes, quadro GitHub e contribuições.

Resumo final: sua UsersAPI já está funcional. O próximo passo não é sair criando coisa nova; é fechar contrato, testar pelo gateway, padronizar retorno, documentar e só depois integrar no front-end.
